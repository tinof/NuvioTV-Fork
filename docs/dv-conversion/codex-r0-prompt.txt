WHAT WE ALREADY ESTABLISHED (verified):
- The fork already converts DV Profile 7 to 8.1 per sample in the extractor (DolbyVisionMatroskaTransformer.kt, DolbyVisionExtractorsFactory.kt) and the Shield plays the result. It can strip HDR10+ SEI (HevcHdr10PlusStripper.kt). The Format (mime/codecs) is rewritten in the extractor before decoder selection; HEVC initializationData is only hvcC, so dvcC never reaches the decoder.
- HDR10+ -> 8.1 is metadata arithmetic (dovi_tool generator.rs parse_hdr10plus_for_l1), CPU-only, microseconds per frame; needs a cargo-ndk Rust staticlib on dolby_vision 3.4 + hdr10plus 2.1.5 (libdovi C API has no per-frame generation).
- CUDA is not usable by apps on Shield Android (CodeWorks for Android ended at CUDA 7.0; cudaErrorInsufficientDriver since Android 8; no NVRTC). The Shield has Vulkan 1.1 drivers. The user proposes a Rust wgpu or raw Vulkan (SPIR-V compute) port of the analysis kernels.
- The RPU must be in the access unit before the decoder receives it, and hdr-analyze's L1 is per scene, so live measured L1 needs lookahead.
- ROADMAP.md puts conversions out of scope of the Shield roadmap; this is a separate track.
